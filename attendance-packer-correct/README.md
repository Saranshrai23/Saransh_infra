# Attendance API AMI with Packer

This folder builds an encrypted Ubuntu 22.04 AMI for the OTMS Attendance API.

The AMI contains:

- Python 3.11
- Poetry and the Attendance API source code
- Gunicorn configured for port `8081`
- PostgreSQL client tools
- Redis client tools
- AWS CLI and `jq`
- `attendance-api.service`
- Runtime support for external AWS RDS PostgreSQL and AWS ElastiCache Redis

The AMI does **not** contain:

- A PostgreSQL server
- A local Redis server
- Database passwords
- RDS or ElastiCache endpoints
- Database migrations

Runtime values are supplied by Launch Template user-data when an Auto Scaling Group instance starts.

## Directory structure


## 1. Prepare variables

```bash
cp dev.pkrvars.hcl.example dev.pkrvars.hcl
nano dev.pkrvars.hcl
```

At minimum, replace:

```hcl
subnet_id = "subnet-REPLACE_WITH_PUBLIC_SUBNET_ID"
```

The temporary Packer instance uses this public subnet to install packages and clone the application repository.

## 2. Build the AMI

```bash
packer init .
packer fmt .
packer validate -var-file=dev.pkrvars.hcl .
packer build -var-file=dev.pkrvars.hcl .
```

After a successful build, Packer writes the generated AMI ID to:

```text
manifest.json
```

## 3. Runtime database and cache configuration

The Launch Template must supply these values to `launch-template-user-data.sh.tpl`:

```text
aws_region
postgres_host
postgres_port
postgres_database
redis_host
redis_port
redis_password
db_secret_arn
```

For the current OTMS Attendance infrastructure:

```text
PostgreSQL port: 5432
PostgreSQL database: attendance_db
Redis port: 6379
Redis password: empty when Redis AUTH is not configured
```

Use the RDS hostname only for `postgres_host`, not a value containing `:5432`.

## 4. Terraform Launch Template example

Use the AMI ID generated by Packer in the Launch Template. The following is the relevant `user_data` section:

```hcl
user_data = base64encode(templatefile(
  "${path.module}/launch-template-user-data.sh.tpl",
  {
    aws_region       = var.aws_region
    db_secret_arn    = aws_db_instance.attendance.master_user_secret[0].secret_arn
    postgres_host    = aws_db_instance.attendance.address
    postgres_port    = aws_db_instance.attendance.port
    postgres_database = aws_db_instance.attendance.db_name
    redis_host       = aws_elasticache_replication_group.attendance.primary_endpoint_address
    redis_port       = aws_elasticache_replication_group.attendance.port
    redis_password   = ""
  }
))
```

When RDS and Redis are managed in another Terraform state, provide these values through remote-state outputs, variables, or AWS data sources instead of direct resource references.

## 5. Required EC2 IAM permission

The EC2 instance profile attached to the Launch Template must allow the Attendance instance to read the RDS-managed master secret:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadAttendanceDatabaseSecret",
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "REPLACE_WITH_RDS_MASTER_SECRET_ARN"
    }
  ]
}
```

If the secret uses a customer-managed KMS key, the role may also need `kms:Decrypt` for that key.

## 6. Required security-group rules

### Attendance application security group

Inbound:

```text
TCP 8081
Source: ALB security group
```

Outbound must permit access to PostgreSQL, Redis, Secrets Manager, and any other required service. A development setup may use all outbound traffic; a production setup can use restricted rules or VPC endpoints.

### PostgreSQL security group

```text
TCP 5432
Source: Attendance application security group
```

### Redis security group

```text
TCP 6379
Source: Attendance application security group
```

RDS and ElastiCache do not need public access.

## 7. Database migrations

Do not run Liquibase during the Packer build. Run database migrations as a separate Jenkins deployment stage from a runner that can reach the private RDS endpoint.

## 8. Verification after an ASG instance starts

```bash
sudo systemctl status attendance-api --no-pager
sudo journalctl -u attendance-api -n 100 --no-pager
sudo cat /var/log/attendance-user-data.log
curl http://127.0.0.1:8081/api/v1/attendance/health
curl http://127.0.0.1:8081/api/v1/attendance/health/detail
```

Check external connectivity when troubleshooting:

```bash
pg_isready -h <RDS_HOSTNAME> -p 5432 -d attendance_db -U attendance_admin
redis-cli -h <REDIS_ENDPOINT> -p 6379 ping
```

Expected Redis response:

```text
PONG
```
